## Findings

1. **P1, unsafe publisher redirects.** `web/src/lib/papers/enrich.ts:84-88,116-120`: DOI validation constrains only the initial URL. `fetch` automatically follows redirect destinations without host/address policy, so a DOI landing target or subsequent redirect can trigger server-side requests to internal services or metadata endpoints. A controlled mocked/local transport test should show unknown/private redirect targets are rejected before a request; no internal host was contacted in this review. Manager approved a bounded trusted HTTPS publisher allowlist and manual redirect validation; deny unknown hosts and limit hops.
2. **P1/P2, source lookup failure becomes false 404.** `web/src/lib/papers/fetch-by-id.ts:21-38,75-107`: OpenAlex and arXiv non-OK responses, network exceptions and timeouts all return null. `web/src/app/api/papers/[id]/route.ts:17-20` and its reading sibling treat null as not found, despite catch-to-503 logic. Separate true 404 from upstream unavailability and independently test metadata and reading responses for 404 and 429/500/timeout.
3. **P1, JSON-LD may attribute another paper's abstract.** `web/src/lib/papers/enrich.ts:55-68,129`: selects the first ScholarlyArticle anywhere in `@graph`, without matching DOI, URL or title; later title-equality check compares abstract text to title, not identity. An invented publisher graph with related article first and requested article second produces wrong-paper source evidence by code path. Match identity or abstain when ambiguous; add that fixture.
4. **P2, successful CAPTCHA response reports missing abstract.** `web/src/lib/papers/enrich.ts:119-133`: publisher HTTP 200 challenge with no abstract remains `missing`; if prior sources also miss, routes see no transient/blocked flag and can cache absence. Full-text detects CAPTCHA but this independent abstract path does not. Detect challenge as blocked/unknown and test resulting no-store behavior.
