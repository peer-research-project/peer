## Route map and evidence discipline

The browser must execute actual UI flows first; use same-account network observations or approved controlled requests for boundary checks. Relevant source routes: `GET /api/papers/upload-availability`, `POST /api/papers/upload/ticket`, `POST` and `GET /api/papers/upload`, `GET/DELETE /api/papers/upload/{id}` and `GET /api/papers/upload/{id}/file`; `GET /api/papers/{id}` and `/reading`, `POST /api/papers/report`; `GET/PUT /api/seed-pool`, `POST /api/seed-pool/assets`, `DELETE /api/seed-pool/assets/{id}`; `/api/feed`, `GET /api/feed/archive?date=YYYY-MM-DD`, `GET /api/jobs/prepare-dashboards`, `GET /api/jobs/dispatch-digests`, `POST /api/profile/send-test-email`. Route names do not establish that every method or request shape is valid: inspect captured application requests and route contracts before exercising them. Uploads use same-origin protection, a rights version and form or signed staging; seed updates use owned asset IDs and `expectedRevision`, and stale updates return 409. Job routes require the configured cron secret and are root-only. Sending a test email is a mutation, not a parity proof.

Record for every case: exact deployment SHA, isolated project identifier (non-secret), account alias, browser/viewport, local date/time and IANA zone, fixture hash or public ID, action, expected/observed result, screenshots or redacted request/status/evidence path, PASS/FAIL/PARTIAL/UNRUN, reviewer and timestamp. Never record cookies, signed URL tokens, provider keys, full test inbox address, personal data or raw private content. Preserve failures and later recovery separately. An unavailable external public source is a truthful transient/blocked result, not an inferred success or paper absence.

Current local report/source and Notes post-fix probes, local rendered UI, mock/job tests and prior historical public controls are useful narrowly scoped evidence, not hosted, SQL, end-to-end or two-round acceptance.
