# C: source identity in reading-availability prefetch

Detached fix `d7632166`, based on main `6e88bdeb`. Availability state, queue and cache keys include the paper's source fingerprint; requests include `sf=1` and the exact fingerprint; cached and fetched readings must match that fingerprint and the reader's version before they can report or cache readable text. Separate source-keyed state prevents a late old-source result from changing the new source. Existing hard readable-body checks, retry behavior, one-day state lifetime and two-request limit remain. Direct reading cache inventory found only this prefetch and `useReading` as direct `readCached`/`rememberReading` callers; card duration and Notes have their separately repaired consumers. The unrelated report cache has its own private `readCached` implementation.

Three targeted suites passed 15/15, including valid prefetch consumed by `useReading`, forged response, forged cache, old response arriving before new, and two concurrent requests. TypeScript no-emit and targeted ESLint both passed with no warnings. A mutation disabling fetched fingerprint validation caused two tests to fail; SHA-256 restored exactly and the targeted gate passed after restoration. Earlier targeted lint had one unused test-parameter warning, corrected before the clean run. No hosted, paid, private-input, or broad-suite claim.
